# Pharma R&D Copilot

A research-support workspace for pharmaceutical development. A scientist submits
a research question; a supervisor agent plans the work, specialist agents
retrieve real literature and patent evidence, and the system produces a
structured report in which **every citation resolves to a source that was
actually retrieved**.

It is decision support. It does not provide medical, regulatory, toxicological,
clinical or legal decisions, and does not replace qualified scientists, patent
counsel, regulatory experts, toxicologists, clinicians or statisticians.

---

## What makes a citation trustworthy here

The central guarantee is structural rather than behavioural:

1. Provider adapters write `evidence_records` rows **before** any synthesis runs.
   Each row gets a stable marker (`E1`, `E2`, …).
2. Synthesis prompts receive only that marker list as citable sources.
3. Every `[En]` marker in generated text is extracted and checked against the
   evidence table. Anything that does not resolve is **removed** and replaced
   with a visible `[unverified citation removed]` flag.
4. The reference list and disclaimers are assembled by code from stored rows,
   not generated by a model.

A model that hallucinates `[E999]` therefore cannot produce a plausible-looking
fake citation. It produces a visibly flagged, stripped claim.

Section confidence is computed from evidence coverage and source breadth, never
from the model's opinion of its own output.

## Architecture

```
Next.js 15 frontend  ──▶  FastAPI  ──▶  Postgres (Supabase)
   Supabase Auth            │              ▲
   middleware guard         │              │
                            ▼              │
                      run_jobs queue       │
                            │              │
                            ▼              │
                     Python worker ────────┘
                            │
                     LangGraph workflow
                            │
              ┌─────────────┼─────────────┐
         PubMed /       EPO OPS        OpenAI
        Europe PMC                  Responses API
```

Research runs take minutes and make dozens of external calls, so they never run
inside an HTTP request. `POST /api/runs` creates the run, enqueues a job and
returns a run id immediately; a separate worker executes the graph and writes a
progress event after every node.

The graph:

```
START → intake_and_scope → supervisor_planner
      → { research_agent, literature_agent, patent_agent }   (concurrent)
      → development_strategy_agent → supervisor_synthesis
      → evidence_reviewer → report_generation → END
```

See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) and
[docs/AGENT_WORKFLOW.md](docs/AGENT_WORKFLOW.md).

## Local setup

Requires **Node 20+**, **Python 3.12+**, and a **Supabase** project.

### 1. Install dependencies

```bash
npm install
```

```bash
python -m venv backend/.venv
```

Windows (PowerShell):

```bash
backend\.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
```

macOS / Linux:

```bash
backend/.venv/bin/python -m pip install -r backend/requirements.txt
```

### 2. Create the database

Apply the migrations in `supabase/migrations/` in filename order, either through
the Supabase SQL editor or the Supabase CLI:

```bash
supabase db push
```

This creates 17 tables, 16 RLS policies and the `private` schema helpers.

### 3. Configure environment

Copy the example file and fill in real values:

```bash
cp .env.example .env.local
```

`.env.local` (frontend) needs:

```
NEXT_PUBLIC_SUPABASE_URL=https://<project-ref>.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=<publishable key>
NEXT_PUBLIC_API_BASE_URL=http://localhost:8000
```

`backend/.env` needs, at minimum:

```
DATABASE_URL=postgresql://postgres.<ref>:<password>@<host>:6543/postgres
SUPABASE_URL=https://<project-ref>.supabase.co
SUPABASE_SERVICE_ROLE_KEY=<service role key>
OPENAI_API_KEY=sk-...
```

All four are required; the backend refuses to start without them and names
exactly which are missing. Provider keys are optional — see
[docs/DATA_SOURCES.md](docs/DATA_SOURCES.md) for what degrades without each.

Find these in the Supabase dashboard under **Project Settings → Database**
(connection string — use the **transaction pooler**, port 6543) and
**Project Settings → API Keys** (service role key).

**No JWT secret is needed.** Current Supabase projects sign tokens with
asymmetric ES256 keys published at `/auth/v1/.well-known/jwks.json`, which the
backend fetches automatically. Confirm yours does too:

```bash
curl https://<project-ref>.supabase.co/auth/v1/.well-known/jwks.json
```

A non-empty `keys` array means you can leave `SUPABASE_JWT_SECRET` blank. Only
legacy projects with an HS256 shared secret need it. `GET /api/health` reports
which scheme is active.

### 4. Check your setup

```bash
cd backend && .venv/Scripts/python.exe check_setup.py
```

Tests every credential and reports pass or fail per item — database connection,
schema completeness, JWT scheme, OpenAI model availability, and each provider.
It prints **no secret values**, so its output is safe to paste when asking for
help.

### 5. Run

Three processes. In separate terminals:

```bash
npm run dev
```

```bash
cd backend && .venv/Scripts/python.exe -m uvicorn app.main:app --reload --port 8000
```

```bash
cd backend && .venv/Scripts/python.exe -m app.worker
```

On macOS / Linux replace `.venv/Scripts/python.exe` with `.venv/bin/python`.

Open http://localhost:3000, create an account, and check
http://localhost:3000/integrations to confirm which providers are live.

### 6. Seed the demo project

Sign up through the web app first, then:

```bash
cd backend && .venv/Scripts/python.exe -m app.seed --email you@example.com
```

This creates the **Peptide Depot Delivery Feasibility Assessment** project with
its research question and parameters. It seeds **no results** — running it
performs a real search and returns whatever the providers actually hold. Add
`--start` to queue the run immediately.

## Tests

```bash
cd backend && .venv/Scripts/python.exe -m pytest -q
```

```bash
npm run lint && npx tsc --noEmit && npm run build
```

The Python suite covers provider normalisation, deduplication, structured model
outputs, citation validation, failed external APIs, missing optional keys, graph
routing, and one end-to-end workflow that runs the real compiled graph against
fixture providers.

## Project layout

```
app/                 Next.js App Router pages
components/          UI, layout, run views
lib/                 API client, Supabase clients, shared types
middleware.ts        server-side route protection
backend/app/
  config.py          settings; required values fail loudly at startup
  auth.py            Supabase JWT verification
  repository.py      all SQL; every read filters by user_id
  api/               HTTP routes
  providers/         PubMed, Europe PMC, EPO OPS adapters
  llm/               Responses API, pricing, prompts, citation validation
  graph/             LangGraph state, nodes, workflow
  worker.py          job queue consumer
  seed.py            demo project
supabase/migrations/ versioned SQL
docs/                architecture, agents, data sources, security, deployment
```
